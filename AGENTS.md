# AGENTS.md

Руководство для агентов, работающих с этим репозиторием.

## Назначение проекта

Проект — лабораторное ПО для метрологических измерений. Состоит из **двух основных программ** и их зависимостей:

- **`devices_logger.py`** — логирование данных с измерительных приборов (Tonghui) с заданным периодом, в реальном времени, с сохранением в файл и графиком.
- **`axes_scanner.py`** — автоматизация серии экспериментов сканирования щелью: читает файл заданий, перемещает ножи (оси APT/APL/APR/APB) через контроллер движения и снимает показания приборов в каждой позиции.

Всё остальное в папке проекта (см. раздел «Игнорируемые файлы») — legacy-скрипты, отдельные утилиты и старые версии. Их НЕ трогать и не учитывать.

## Обязательные правила

1. Работать только с файлами, относящимися к `devices_logger.py` и `axes_scanner.py` (см. разделы ниже).
2. Запускать программы ТОЛЬКО из корня проекта (пути в коде относительные).
3. Комментарии в коде и вывод программ — на русском (существующий стиль).
4. Зависимости (`requirements.txt`) не урезать: там указаны также пакеты для игнорируемых утилит.
5. `Data/` — рабочий каталог данных, он в .gitignore; результаты туда пишутся автоматически. `Temp/` — тоже рабочий каталог, но по задумке он НЕ игнорируется системой контроля версий (его содержимое может попадать в репозиторий).
6. Не менять механизм подключения дамми-библиотек (см. раздел «Дамми-библиотеки»).
7. Журнал изменений (`Log/`) не создавать и не переписывать по своей инициативе: новый файл `changelog_<дата>.txt` создаётся по решению автора и описывает изменения после предыдущего журнала.

## Как запускать

Основные аргументы CLI задокументированы в `instruction.txt` (источник истины). Кратко:

### devices_logger.py

```
python devices_logger.py -d "ОПИСАНИЕ_УСТРОЙСТВ" [ОПИСАНИЕ_УСТРОЙСТВ ...] \
    [-fs] [-pl key=value ...] [-np] [-ho] [-p СЕК] [-f ИМЯ] [-n ТОЧКИ] [-cp ТОЧКИ]
```

- `-d` / `--devices` — приборы, каналы, пресеты, записываемые величины и графики (полный синтаксис — в `instruction.txt`).
- `-fs` / `--faststart` — запуск без предварительной настройки приборов.
- `-pl` / `--plot` — габариты окна/полотен (`width`, `height`, `canvas_height`, `n_cols`, `figure_width_step`).
- `-np` / `--noplot` — не создавать графики, даже если в `-d` указаны метки `@`.
- `-ho` / `--hold` — не закрывать окно графика по завершении программы.
- `-p` / `--period` — период шага измерения, сек (по умолч. 1.0).
- `-f` / `--filename` — имя файла результатов; если не задано — генерируется автоматически.
- `-n` / `--points` — число измерений (по умолч. 999999).
- `-cp` / `--canvaspoints` — точек по оси X на графике (по умолч. 3600).

Пример:
```
python devices_logger.py -d "TH1992B_1.ch1~APL_I=CURR,VOLT@ток;ch2~APL_I=CURR@ток" TH2690A_1~FDUK=CURR@ток -n 300 -cp 200 -fs
```

### axes_scanner.py

```
python axes_scanner.py -d "ОПИСАНИЕ_УСТРОЙСТВ" [ОПИСАНИЕ_УСТРОЙСТВ ...] \
    [-r ИНДЕКСЫ 0 2 3] [-tf ПУТЬ_К_ЗАДАНИЮ] [-fs] [-pl key=value ...] [-np] [-ho] [-sf] [-x time|APT|APL|APR|APB]
```

- `-d` / `--devices` — приборы, каналы, пресеты, записываемые величины и графики (полный синтаксис — в `instruction.txt`).
- `-r` / `--run` — индексы экспериментов из файла заданий (по умолч. все).
- `-tf` / `--taskfile` — путь к файлу заданий (по умолч. `Axes_scan_default.txt`).
- `-fs` / `--faststart` — запуск без предварительной настройки приборов.
- `-pl` / `--plot`, `-np` / `--noplot`, `-ho` / `--hold` — как в логгере.
- `-sf` / `--singlefile` — сохранять все эксперименты в один файл.
- `-x` / `--xaxis` — ось X графика по умолчанию; задание может переопределить её столбцом `x_axis`.

Пример:
```
python axes_scanner.py -d "TH1992B_1.ch1~APL_I=CURR,RES@scan;ch2~APL_I=CURR@scan" -tf EXP2_APL+APT.txt
```

## Ключевые конвенции и точки интеграции

### 1. Пул приборов и синтаксис `-d` (`Complex_libs/DeviceSpecParser.py`, `Complex_libs/Devices.py`)

- `Devices.ini` задаёт состав устройств в едином формате: `type`, `model`, `folder`, `interface`, `address`, `channels`, `values`, `units` (для контроллера — `axes`, `axesnames`, `units`). Адрес для `tcpip` задаётся как `ip:port`.
- Разбор выполняет `DeviceSpecParser`: читает `Devices.ini`, разбирает `-d` и отдаёт совместимый с инициализацией пул (ключи `LibraryFolder`, `LibraryName`, `ConnectionMethod`, `DeviceAddress`, `DevicePort`, `Channels`).
- Синтаксис CLI: `<имя>[.ch<номер>][~<пресет>]=<величины>[;ch<номер>...]`, каждая величина — `<величина>[@<полотно>]`. Полный синтаксис — в `instruction.txt`.
- Если `~` не указан — прибор запускается без настройки (`FastStart`); флаг `-fs` переводит всё в этот режим.
- Драйвер подключается динамически: `importlib.import_module(f"{folder}.{model}")` → класс `Device`.
- Секция контроллера `ACS` (`axes`, `axesnames`, `units`) пока не потребляется кодом: имена осей задаются в `TaskFileParser.AXES`, а контроллер создаётся с адресом прямо в `axes_scanner.py`.

### 2. Контракт драйвера прибора

Любой драйвер (в т.ч. дамми) обязан реализовывать класс `Device` с методами:

- `Initialize(**connection_details)` → bool;
- `ConfigureDevice(ConfigName)` → bool (`ConfigName` — строка пресета или `{канал: пресет}` для многоканальных);
- `SingleMeasure()` → dict вида `{'CURR1': ..., 'RES1': ..., 'VOLT1': ...}` (ключи — имена величин; для многоканального прибора суффикс — номер канала).

`Devices` после настройки делает пробное `SingleMeasure()`, оставляет только запрошенные в `-d` величины и формирует `device_data_keys` (ключи данных) и `device_columns` (прибор, канал, величина, единица — из них строится шапка файла).

### 3. Гибкая замена драйверов (тестирование без железа)

Дамми-библиотеки включаются НЕ через код или конфиги, а **временным переименованием файлов**. Это временный приём для отладки и тестирования без оборудования: в репозитории (в гите и на GitHub) всегда лежат настоящие файлы под настоящими именами, а состояние с подменёнными файлами никогда не коммитится.

- **Tonghui**: дамми `__tonghui_TH1992B.py` переименовывается в `tonghui_TH1992B.py`, а настоящий `tonghui_TH1992B.py` — во `tonghui_TH1992B_.py` (или `_real`). То же для `__tonghui_TH2690A.py`/`tonghui_TH2690A.py`. `Tonghui_libs/__init__.py` и `Devices.ini` не меняются — импорт идёт по имени.
- **Motion_control**: дамми `__init__dummy.py` переименовывается в `__init__.py`, а настоящий `__init__.py` — в `__init__.py_` (или `__init__real.py`).
- После окончания отладки имена возвращаются как были (реальный файл — основное имя, дамми — с `__`/суффиксом `dummy`).
- После переименования полезно очистить `__pycache__`, чтобы не подхватывался устаревший байткод.

### 4. Файлы заданий axes_scanner (`User_libs/TaskFileParser.py`)

Парсинг — по именам столбцов (заголовок в первой непустой строке, может начинаться с `#`),
поэтому порядок столбцов произвольный, а новые можно добавлять в середину/конец.
`ParseTaskFile` в `pyTools.py` — тонкая обёртка над `TaskFileParser` (совместимость).

```
#APT	APL	APR	APB	intvls	post_delay	filename	x_axis
10:20	20	20	20	15	0.5	test_file_1.txt	APT #здесь можно комментарий написать
10:25	25	25	25	15	0.1	test_file_2.txt	APT
```

- Обязательные столбцы: `APT APL APR APB` и `intvls` (иначе `[ОШИБКА]`).
- Необязательные: `post_delay` (0.0), `filename` (генерируется), `x_axis` (`time` или имя оси; переопределяет глобальный `-x`).
- Алиасы: `intervals`→`intvls`, `xaxis`/`x`→`x_axis`; регистр не важен.
- Неизвестные столбцы игнорируются с одним `[WARNING]` на файл.
- Значение оси: диапазон `start:end` или одиночное число (ось неподвижна, `is_used=False`).
- `intvls` — число интервалов; координаты строятся через `np.linspace(start, end, intervals + 1)`.
- Номера осей для контроллера: порядок из `TaskFileParser.AXES` (`APT=0, APL=1, APR=2, APB=3`).

### 5. Движение осей (`Motion_control`)

- `Controller` общается с контроллером ACS по TCP-сокету.
- `InitSpeed(acs)` — включение осей и установка скоростей.
- `MoveBlades(acs, axes, cpos)` — на `cpos==0` двигает все оси в `start`, далее только используемые (`is_used`). Обновляет позиции для графика.
- `axes_scanner.py` в каждом шаге вызывает `move_blades` как `row_prefix_callback`: координаты осей дописываются в строку результата.

### 6. Цикл измерения и файл результата (`measurement.py`)

- `MeasurementSession.run_measurement_loop(num_points)` — последовательный проход: параллельно опрашивает все приборы (потоки), формирует TSV-строку `время + prefix + значения`.
- Заголовок пишется при `file_mode='w'` через `build_file_header` в формате `<прибор>[.ch<номер>]=<величина>, <единица>` (колонки берутся из `device_columns`), сброс буфера на диск — раз в минуту.
- Имя файла по умолчанию — `<режим>_<гггг>-<мм>-<дд>_<чч>-<мм>-<сс>` (режим: `logger` в логгере или имя файла задания в сканере); явно заданное имя используется как есть; при совпадении имён добавляется `(1)`, `(2)` и т.д.
- При наличии меток `@полотно` в `-d` строится `Plotter` (полотна одного окна); ключ `-np` отменяет построение графиков, `-pl` задаёт габариты окна/полотен. График сохраняется в PNG рядом с .txt; Ctrl+C сохраняет рисунок и завершает программу.
- Путь сохранения: `CreateSavePath('\\\\MetroBulk\\Public\\EXP_DATA')` — при доступности сетевого хранилища туда, иначе локально в `Data/<ГГГГ_ММ_ДД>/`; имя файла уникализируется (суффикс `(n)`).

### 7. График (`User_libs/pyPlotter.py`)

- `Plotter` принимает структурированные описания кривых от `DeviceSpecParser` (`device`, `key`, `channel`, `value`, `unit`, `canvas`).
- Метки `@имя` в `-d` задают полотна (subplot) внутри одного окна; полотна располагаются вертикально. Внутри полотна линии делятся на левую/правую половины осей Y.
- Тики оси Y выводятся как `.3f` с физической приставкой СИ и базовой единицей из `units` в `Devices.ini` (например, `-90.000 pA`, `1.234 mA`, `4.560 MOhm`); научной нотации и offset-текста `1eN` нет. Подпись оси — имя кривой.
- Настройки форматирования (размер окна, высота полотна, отступы, шрифты и т.д.) собраны в классе `PlotConfig`; часть из них переопределяется ключом `-pl`: `width`, `height`, `canvas_height`, `n_cols`.
- Раскладка выполняется движком `constrained` (сам резервирует место под подписи и тики); перерисовка ограничена по частоте (`render_period`), чтобы не тормозить измерения.
- Ключ `-g` удалён — графики задаются метками `@` в `-d`.

## Журнал изменений (папка `Log/`)

В папке `Log/` хранится журнал изменений проекта — человекочитаемое описание того, что и зачем менялось. Файлы называются `changelog_ГГГГ_ММ_ДД.txt` (дата в том же формате, что и у каталогов данных `Data/`).

Порядок работы:

- Журнал ведётся не автоматически, а по решению автора проекта: когда накопится достаточно изменений, автор создаёт новый файл `changelog_<дата>.txt`.
- Новый журнал описывает все изменения, произошедшие после предыдущего; старые файлы не переписываются.
- Файл делится на две части: «Что изменилось» — для пользователя программ, и «Что изменилось в коде» — для разработчика.
- Язык — русский; каждый абзац пишется одной строкой (переносы делает редактор); стиль безличный («переработан запуск…», «раньше … теперь …»), без сокращений и телеграфных фраз.
